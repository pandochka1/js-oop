Теория

Зачем нужны классы learn.javascript.ru/class

Когда программа работает с одним объектом, достаточно обычного литерала. Но как только в проекте появляется много однотипных объектов — пользователей, сессий, сетевых пакетов — нужен способ описывать их «по образцу». Именно эту роль выполняет класс: он задаёт структуру и поведение, а каждый конкретный объект создаётся из этого образца.

Объект, который появляется по описанию класса, называют экземпляром (instance). Класс описывает «тип», экземпляр — «конкретный представитель» этого типа. Например, класс User описывает любого пользователя, а экземпляр с именем "Мария" — конкретного пользователя.

Классы в JavaScript появились как «синтаксический сахар» поверх прототипного наследования — но за этим сахаром стоит заметное упрощение кода. Один класс заменяет конструктор-функцию, план свойств и описание методов, которые раньше нужно было собирать вручную.

Кибербезопасность
Классы отлично подходят для моделей предметной области, где важны ограничения. Класс User, который сам проверяет свои права, или Session, которая сама следит за сроком жизни, — это распространённый приём при построении безопасных веб-систем.
Синтаксис класса: конструктор, поля, методы learn.javascript.ru/class

Минимальный класс состоит из имени, метода-конструктора и одного-двух методов:

class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  isAdult() {
    return this.age >= 18;
  }
}
  • class User — объявление класса. По договорённости имя класса пишут с большой буквы.
  • constructor(...) — специальный метод, который вызывается автоматически при создании экземпляра через new. В нём обычно инициализируют поля объекта.
  • this — ссылка на создаваемый / текущий объект. Через this.name = ... мы сохраняем значение в поле конкретного экземпляра.
  • Обычные методы — функции, которые имеет каждый экземпляр. Они записываются без ключевого слова function и запятой между ними не требуется.
  • Между методами запятые не ставятся — это частaя ошибка у тех, кто переходит с объектов-литералов.

Создание экземпляра выполняется оператором new:

let user = new User("Олег", 21);
console.log(user.name);   // Олег
console.log(user.isAdult()); // true

Без new класс вызвать нельзя — это важное отличие от обычных функций. Вызов User("Олег", 21) приведёт к ошибке.

Приватные поля и геттеры learn.javascript.ru/private-protected-properties-methods

Не все данные объекта должны быть видны снаружи. Пароль, токен, ключ шифрования — это внутренние секреты, доступ к которым нужно ограничить. Для этого существуют приватные поля — они начинаются с символа решётки #:

class Session {
  #token;
  #expiresAt;

  constructor(ttlMin) {
    this.#token = Math.random().toString(36).slice(2);
    this.#expiresAt = Date.now() + ttlMin * 60000;
  }

  get token() {
    return this.#token;
  }
}

Приватное поле #token доступно только внутри класса. Попытка обратиться к session.#token снаружи вызовет ошибку. Это и есть инкапсуляция: скрытие внутреннего состояния за интерфейсом.

Чтобы контролируемо отдавать данные наружу, используют геттеры — методы со словом get. Снаружи геттер вызывается как обычное свойство, без скобок:

let s = new Session(30);
console.log(s.token);   // вызовет геттер, вернёт токен
// s.#token — ошибка, поле недоступно

Геттер — это не «просто переменная», а метод: внутри него можно выполнять логику, например, скрывать часть данных.

Кибербезопасность
Инкапсуляция в программировании — близкий родственник «минимальных привилегий» в безопасности. Чем меньше данных снаружи, тем труднее случайно раскрыть секрет или сломать внутреннюю логику. Токен сессии, хранящийся в приватном поле, не «вытечет» в случайный вызов console.log, если сам класс того не позволяет.
Сеттеры и проверка данных

Если геттер читает значение, то сеттер — записывает его, и при записи можно выполнить проверку. Это удобно для валидации входных данных:

class Account {
  #password;

  constructor(login) {
    this.login = login;
    this.#password = "";
  }

  set password(value) {
    if (value.length < 8) {
      throw new Error("Пароль слишком короткий");
    }
    this.#password = value;
  }

  get password() {
    return "***";
  }

  check(value) {
    return this.#password === value;
  }
}

Сеттер set password вызывается при присваивании acc.password = "...". Если пароль короче 8 символов — бросается исключение, и значение не сохраняется.

Важно понимать: сеттер — это метод, а не просто «поле без ограничений». Он даёт единственную точку, где все данные проходят через проверку. Это надёжнее, чем проверять каждый раз снаружи класса.

Метод check сравнивает переданное значение с сохранённым — так проверяют пароль, не выдавая сам пароль наружу. Реальный пароль наружу вообще не отдаётся — наружу доходит только результат сравнения true/false.

Кибербезопасность
Проверка пароля «изнутри» объекта, без доступа к самому паролю, — базовый принцип. Хеш пароля тоже сравнивают именно так: наружу выходит только бит «совпало / не совпало», а не сам хеш. Сеттер с валидацией — первый шаг к этому на уровне кода.
Наследование: extends и super learn.javascript.ru/class-inheritance

Классы позволяют строить иерархии: один класс может взять поля и методы другого и дополнительно задать своё. Это называется наследованием.

class BaseUser {
  constructor(name) {
    this.name = name;
  }
  role() {
    return "пользователь";
  }
}

class Admin extends BaseUser {
  constructor(name, department) {
    super(name);
    this.department = department;
  }
  role() {
    return "администратор";
  }
}
  • extends — указывает, что класс Admin наследует от BaseUser.
  • super(...) — вызов конструктора родителя. Он обязан быть первым вызовом в теле дочернего конструктора, до использования this.
  • super.method() — обращение к методу родителя. Позволяет расширить код родителя, а не копировать его.
  • Переопределение — дочерний класс может переписать метод родителя с тем же именем.

Экземпляр Admin имеет и поля родителя (name), и собственные (department). Наследование «по наследству» передаёт базовое поведение, а дочерний класс добавляет специфику.

Кибербезопасность
Иерархия ролей — классика. Класс BaseUser описывает общего пользователя, а Admin, Auditor, Operator наследуют его и расширяют права. Это естественная модель для разграничения доступа (RBAC), где более привилегированная роль базируется на менее привилегированной.
Статические методы learn.javascript.ru/static-properties-methods

Иногда метод принадлежит не отдельному экземпляру, а самому классу в целом. Такие методы называют статическими и помечают словом static:

class AuditLog {
  constructor() {
    this.entries = [];
  }

  static format(entry) {
    return entry.time + " [" + entry.level + "] " + entry.message;
  }

  log(level, message) {
    this.entries.push({ time: Date.now(), level, message });
  }
}

Статический метод format вызывается через имя класса, а не через экземпляр:

let formatted = AuditLog.format({ time: 123, level: "warn", message: "x" });
// Обычный метод log — через экземпляр:
let logger = new AuditLog();
logger.log("warn", "внимание");

Статические методы удобно использовать для вспомогательных операций, которые не зависят от конкретного объекта, — форматирование, конвертация, фабрики создания объектов.

Примеры с пошаговым разбором

Пример 1

Класс User и проверка прав

Создать класс User с полями name и role и методом canAccess(), который проверяет права на действие по роли. Это пример разграничения доступа на уровне объекта. 
class User {
  constructor(name, role) {
    this.name = name;
    this.role = role;
  }

  canAccess(action) {
    const matrix = {
      admin:  ["create", "read", "update", "delete"],
      editor: ["create", "read", "update"],
      viewer: ["read"]
    };
    const rights = matrix[this.role];
    return rights ? rights.includes(action) : false;
  }

  describe() {
    return this.name + " (роль: " + this.role + ")";
  }
}

let user = new User("Олег", "editor");
console.log(user.canAccess("delete")); // false
console.log(user.describe());
Построчное пояснение
class User {Начинаем объявление класса User.
  constructor(name, role) {Конструктор принимает имя и роль. Вызывается автоматически при new User(...).
    this.name = name;Сохраняем имя в поле создаваемого объекта.
    this.role = role;Сохраняем роль в поле создаваемого объекта.
  canAccess(action) {Метод проверяет, можно ли выполнить действие с текущей ролью.
    const matrix = { ... };Словарь «роль → список разрешённых действий». admin может максимум, viewer — только читать.
    const rights = matrix[this.role];Берём список прав для роли данного экземпляра.
    return rights ? rights.includes(action) : false;Если роль найдена — проверяем наличие действия через includes(); если роли нет в словаре (например, "hacker") — false.
  describe()Вспомогательный метод — формирует строку-описание объекта.

Пример 2

Класс Session с приватным токеном

Сессия хранит токен, который не должен «вытечь» наружу. Поле #token — приватное. Снаружи доступен только геттер и методы проверки. 
class Session {
  #token;
  #expiresAt;

  constructor(user, ttlMin) {
    this.user = user;
    this.#token = Math.random().toString(36).slice(2) + Math.random().toString(36).slice(2);
    this.#expiresAt = Date.now() + ttlMin * 60000;
  }

  get token() { return this.#token; }

  isValid() { return Date.now() < this.#expiresAt; }
}

let s = new Session("guest", 30);
console.log(s.token);      // через геттер
console.log(s.isValid());  // true

Класс Account: сеттер с проверкой пароля

Аккаунт хранит пароль в приватном поле. Сеттер проверяет длину, геттер не раскрывает реальный пароль, а метод check() сравнивает значения изнутри.

Пример 4

Наследование: Admin extends BaseUser

Класс Admin наследует поля и методы BaseUser, добавляет собственное поле department и переопределяет метод role(). Через super() вызывается конструктор родителя. 
class BaseUser {
  constructor(name) {
    this.name = name;
  }
  role() { return "пользователь"; }
}

class Admin extends BaseUser {
  constructor(name, department) {
    super(name);
    this.department = department;
  }
  role() { return "администратор"; }
  full() {
    return super.role() + " → " + this.role() + " из одела " + this.department;

Пример 5

Класс AuditLog со статическим методом

Журнал событий безопасности. Метод log() добавляет запись, статический format() форматирует одну запись — он не зависит от конкретного экземпляра и вызывается через имя класса. 
class AuditLog {
  constructor() {
    this.entries = [];
  }

  static format(entry) {
    return new Date(entry.time).toISOString() + " [" + entry.level + "] " + entry.message;
  }

  log(level, message) {
    this.entries.push({ time: Date.now(), level, message });
  }

  latest() {
    const last = this.entries[this.entries.length - 1];
    return last ? AuditLog.format(last) : "записей нет";
  }
}

let logger = new AuditLog();
logger.log("warn", "Подозрительное действие");
console.log(logger.latest());
Построчное пояснение
constructor() { this.entries = []; }Каждый журнал начинает с пустого массива записей.
static format(entry)Статический метод — принадлежит классу, а не экземпляру. Вызывается как AuditLog.format(...).
  return new Date(entry.time).toISOString() ...Превращает метку времени в читаемую строку и собирает [уровень] сообщение.
log(level, message)Обычный метод — добавляет запись в массив entries экземпляра.
  this.entries.push({ time: Date.now(), ... });Записываем момент, уровень и сообщение.
latest()Возвращает последнюю запись в отформатированном виде.
  return last ? AuditLog.format(last) : "записей нет";Если записей нет — возвращает текст, иначе форматирует последнюю через статический метод.
let logger = new AuditLog();Создаём экземпляр журнала.
logger.log("warn", "Подозрительное действие");Добавляем запись уровнем warn.
console.log(logger.latest());Выводим последнюю запись в форматированном виде.

5 задач по аналогии с разобранными примерами. Соседние задачи устроены как примеры — используйте их как образец.

1

Класс Event

лёгкая
По аналогии с примером User: класс Event с полями name, severity (уровень серьёзности) и методом isCritical(), который возвращает true, если severity ≥ 8.
2

Класс Token

лёгкая
По аналогии с примером Session: класс Token с приватным значением #value и методом length(), который возвращает длину токена (но не сам токен).
3

Класс IpAddress с проверкой

средняя
По аналогии с примером Account: класс IpAddress. Поле #ip приватное. Сеттер ip проверяет, что строка выглядит как адрес (должна содержать ровно 3 точки), иначе бросает исключение. Добавьте геттер и метод isValid().
4

Наследование: Auditor extends BaseUser

средняя
По аналогии с примером Admin: класс Auditor наследует от BaseUser, добавляет поле region и переопределяет role() на «аудитор». Метод describe() возвращает имя + роль + регион.
5

Класс Registry со статическим методом

сложная
По аналогии с примером AuditLog: класс Registry хранит список записей. Добавьте статический метод countByLevel(entries, level), который возвращает, сколько записей имеют заданный уровень.

1

Чем класс отличается от экземпляра? Приведите аналогию из жизни и из области безопасности.

2

Зачем в конструкторе используется this? Что сохраняется через this.name = name?

3

Объясните инкапсуляцию на примере приватного поля #token в классе Session. Почему метод isValid() не раскрывает сам токен?

4

В чём смысл проверки пароля «изнутри» класса через сеттер и геттер, возвращающий «***»? Как это связано с принципом минимальных привилегий?

5

Что происходит в классе Admin, когда в конструкторе вызывается super(name)? Почему super() должен идти первым?

6

Чем отличаются обычные методы, приватные поля и статические методы? Когда уместен статический метод (как в AuditLog.format)?

7

Как наследование позволяет моделировать роли доступа (BaseUser → Admin, Auditor)? Какие преимущества даёт такое наследование?

8

Что вернёт выражение user.canAccess("delete") для роли viewer? Объясните, как метод это определяет.

9

Приведите пример из ИБ, где геттер или сеттер помогает защитить данные (токен, пароль, IP-адрес).

10

Почему для сравнения пароля используется метод check(), а не геттер, возвращающий сам пароль? Что передаётся наружу и почему это безопаснее?

Как запускать код

1. Откройте терминал в VS Code: Ctrl + `
2. Скопируйте код примера в файл oop.js и запустите: node oop.js
3. Для своих задач: создайте отдельный файл, например task.js

Классы в Node.js работают без дополнительных настроек — просто сохраните код и запустите файл.
